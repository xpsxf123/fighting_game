# 《大蜀国物语》分阶段项目计划

> 版本：v0.1  
> 配套文档：`GDD-大蜀国物语.md` · `贴图资产清单-大蜀国物语.md`  
> 原则：**每阶段开工前必须完成「设定问答门」**；未确认项不得凭空实现。

---

## 0. 协作规则（必读）

### 0.1 阶段门（Phase Gate）

每个阶段固定四步：

```
① 问答调研（你回答） → ② 更新本阶段说明书 → ③ 开发/制作 → ④ 验收试玩 → 过门进入下一阶段
```

- **① 问答**：我只问「本阶段决策所必需、且 GDD 里尚未敲定」的问题。  
- **你可答**：选项 / 自由描述 /「按你推荐」 /「本阶段先跳过」。  
- **未回答且无默认**：相关功能本阶段不做。  
- **过门条件**：达到该阶段「验收清单」；不追求完美美术（除明确标注的阶段）。

### 0.2 问答记录

答案写入：`docs/阶段问答记录.md`（按阶段追加）。  
冲突时以**最新问答答案**覆盖 GDD 草稿默认值。

### 0.3 范围控制

| 允许 | 不允许 |
|------|--------|
| 本阶段验收清单内的内容 | 提前做下一阶段大系统 |
| 修上一阶段阻塞 Bug | 无问答就改核心设定（货币名、职业名等） |
| 小幅数值试调 | 一次性铺满 46 坊巷 / 全建筑 |

**本阶段不做**：写业务代码、大规模出图。

---

### S1 — 可玩玩具（Vertical Slice）

**目的**：用最小内容验证 Essential Experience（会呼吸的城 / 坊巷爽感 / 年贡反馈）。

**范围（建议）**：
- 单地图：平畴乡缩小版
- 时间流逝 + 速度档
- 建造：宅基、土路/木路、田、货栈、井、园圃、3～7 店、住房低阶、州城可延后到 S2
- 2～4 名住民：走、进店、耕田、头顶冒泡（金币/研策可简化为一种）
- **1 个坊巷**：宵夜巷（面馆+抄手+火锅）成立演出
- **1 次年贡**结算面板
- 助手青荷 3～5 句教程
- 临时美术可占位（色块或 AI 草图），但地形风格需你点头

**验收清单**：
1. 能从新档玩到「组成坊巷」并感到反馈  
2. 能触发一次年贡  
3. 住民会自主走动（非纯静态）  
4. 你主观：愿意「再多摆两栋试试」  

**本阶段不做**：转职树、工巧、客旅、全国排名、三地图、46 坊巷。

> S1 经济已按对照文档落地（进店不进玩家口袋）。完整表驱动与州城等见 `数值与逻辑-大江户对照.md`。

### S1b — 逻辑骨架（已并入 S1）

原独立阶段内容已实现于 `dashu-town/js/game-core.js`，验收见 `docs/phases/S1-说明书.md` §4。不再单独排期。

### S2 — 成长系统

**目的**：前中期「解锁→变强→再解锁」循环成立。

**范围**：
- 四维属性 + 商店对属性修正（可先少量）
- 四色研策 + 研究解锁建筑
- 职业五阶基础（至少农/匠/商 + 转职入口）
- 州城：建造、不可拆、辐射加成、解锁转职
- 住房改建链（做到瓦屋或木楼即可）
- 存档读写 v1

**验收**：不靠作弊，能自然玩到「筑城 + 转职至少一次」；研究能解锁 3+ 新建筑。

**本阶段不做**：工巧完整、客旅、排名大奖、载具高阶。

---

### S3 — 中期系统

**目的**：对齐原作中期厚度，兴趣曲线不塌。

**范围**：
- 货栈 5×5 工巧发现 + 制作/使用/升级（先 8～15 种）
- 客栈 + 客旅（先 4～6 团）
- 全国粮赋排名 + 2～3 个排名解锁建筑
- 载具：驴马（白马可后置）
- 坊巷扩到 10～15 个
- 建筑池扩到「能玩 5～8 年不空虚」

**验收**：一局能玩到中期；工巧/客旅/排名各至少完整闭环一次。

---

### S4 — 内容填满

**目的**：体量接近可发售的内容完整度。

**范围**：
- 三开局地图（平畴乡 / 剑门谷 / 锦江浦）
- 坊巷冲到目标数（默认 46，可以问答砍到 30）
- 环境/商店/设施按清单补全
- 工巧、客旅补全
- 州城最多 3 座条件
- 二周目继承表（可先数据、后 UI）

**验收**：内容表无大洞；三地图均可开局；一局 15～16 年目标可玩通。

---

### S5 — 表现与体验打磨

**目的**：从「能玩」到「愿意推荐」。

**范围**：
- 按贴图清单替换占位图；统一锚点与色板
- BGM/SFX
- UI 可用性、教程、报纸/事件文案
- 数值平衡（年贡、维护费、成功率）
- 无障碍：速度、字体、跳过对话

**验收**：你指定的 3 名试玩者（或你自己冷启动）能无讲解通过前 30 分钟；无阻断级 Bug。

---

### S6 — 发布候选

**目的**：可分发/上架。

**范围**：
- 安装包 / 商店页素材
- 崩溃与存档损坏防护
- 成就（可选）、语言（至少简中）
- 已知问题列表与版本号

**验收**：干净机器新装可玩；存读档 20 次无坏档；发布清单勾完。

## 8. 平台评估：开罗式轻量经营 × 微信

### 8.1 结论

| 问题 | 结论 |
|------|------|
| 这种游戏适不适合微信？ | **适合**，且受众匹配（碎片、触控、轻经营） |
| 该做成「小程序」还是「小游戏」？ | **应做成微信小游戏**；普通小程序也能塞 Canvas，但工具链、性能、包体、输入都更别扭 |
| 和原版开罗手机版比？ | 玩法同级可行；需为**包体、性能、触控 UI**做减法 |

### 8.2 为什么适合

1. **品类匹配**：开罗式是点选+时间流逝，不是高帧硬核；微信上同类经营/放置很多。  
2. **会话匹配**：你选了 4～6h 短局，天然适合「打开玩一会再关」。  
3. **技术匹配**：2D 格子 + 少量小人，控制好数量就能跑。  
4. **分发匹配**：即便先自玩，开发者工具 / 体验版就够；以后要上架也有路径。

### 8.3 主要约束（必须提前认）

| 约束 | 对《大蜀国物语》的影响 |
|------|------------------------|
| 主包体积有限 | 色块占位正确；真图要压缩、分包 |
| 同时大量小人 | S1 先 2～4 人；后期做视野裁剪/简化动画 |
| 存档 | 用 `wx.setStorage` / 本地用户文件，勿当 PC 文件系统 |
| 触控 | 大按钮、少悬停；建造用「选建筑→点地」 |
| 审核（若上架） | 赌坊等敏感建筑可换成「戏票行」等；先自玩无压力 |
| 后台 | 小游戏通常**前台才跑时间**（对齐开罗「打开才推进」其实更贴） |

### 8.4 引擎推荐（答 D）

| 方案 | 适合度 | 说明 |
|------|--------|------|
| **Cocos Creator 3.x** | ★★★★★ | 微信小游戏文档全、案例多，**首选** |
| Unity + 微信导出 | ★★★ | 能出，但包体与链路更重，轻量项目不划算 |
| Godot | ★★ | 微信官方路径弱，不建议作首选 |
| 裸 Canvas / Pixi | ★★★★ | 最轻，但什么都要自己搭，里程碑制下更累 |

**锁定推荐：Cocos Creator 3.x → 微信小游戏。**
